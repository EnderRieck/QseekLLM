# 大语言模型预训练系统中期报告

## 1. 研究目标与总体规划概述

本课程设计题目为“面向中英双语推理能力的小规模大语言模型预训练与 GRPO 后训练框架设计”。项目总体目标不是单纯追求最终模型分数，而是构建一条可运行、可复现、可分析的小规模大语言模型训练链路，覆盖数据清洗与配比验证、Tokenizer 训练、小模型预训练验证、1.7B 级别基础模型预训练、中英双语 SFT、推理冷启动、GRPO 强化学习后训练和综合评测。

本项目由张子路和郭子逸 2 名成员共同完成，分别负责数据准备+预训练阶段，以及后训练+推理优化阶段。本文主要汇报当前已经完成的预训练侧工作和与其配套的评测基础设施，包括多源数据下载与清洗、tokenizer 训练、流式训练数据读取、异步 tokenization、分布式训练、checkpoint 保存、推理接口和测评接口。当前已经使用 700M 规模模型完成 10B tokens 级别试训练，并基于 Chinese WPLC 与 LAMBADA 两个Benchmark进行阶段性测评。

截至目前，项目已经完成数据准备、Tokenizer、训练框架、700M 试训练和初步测评闭环。按原始规划估算，当前整体完成度约为 **35%-40%**，已经达到并超过中期阶段至少 30% 的进度要求。

## 3. 数据集下载与预处理进展

### 3.1 数据来源

开题报告规划准备约 50B tokens 预训练数据，覆盖中文通用、英文通用、代码、数学、论文和百科六类数据。当前已在配置中接入或预留的主要数据源包括：

| 数据域 | 数据来源 |
| --- | --- |
| 中文通用 | CCI3.0-HQ、ChineseWebText 2.0 |
| 英文通用 | FineWeb-Edu、Dolma |
| 代码 | The Stack v1、CodeNet |
| 数学 | OpenWebMath、Proof-Pile-2、本地数学抽取数据 |
| 论文 | MinerU 论文解析统一格式数据 |
| 百科 | zhwiki、enwiki |

其中 The Stack v1 已完成下载，并单独完成了预处理流程；The Stack v2 因数据量和下载方式成本较高，当前没有作为主数据源使用。论文域目前仍处于预留状态，在当前 700M 训练混合配置中权重暂设为 0，后续在论文数据质量和格式稳定后再加入正式训练。

### 3.2 预处理流程

数据预处理配置位于 `configs/preprocess/stage0_stream_preprocess.yaml`，核心流程包括：

- 多源 JSONL / Parquet 流式读取；
- 文本长度过滤，当前最小长度为 80 字符，最大长度为 200000 字符；
- Unicode 规范化、空白字符规范化和 boilerplate 清理；
- 控制字符比例、重复行比例、字母或中日韩字符比例等启发式质量过滤；
- 精确去重已启用；
- simhash 近似去重当前关闭，避免在当前大规模数据上耗时过久；
- 预处理 worker 数量为 64；
- 输出 manifest 用于后续训练流式读取。

当前训练入口使用的 manifest 路径为：

```text
llmTrain/runs/stream_preprocess/manifest.jsonl
```

训练流程不依赖手工拼接数据文件，而是通过统一 manifest 管理清洗后的 shard，为后续多机或更大规模训练提供了基础。

### 3.3 当前训练数据配比

当前 700M 训练配置使用的数据混合比例位于 `configs/data/mixture_50b.yaml`：

| 数据域 | 当前权重 |
| --- | ---: |
| 中文通用 | 0.35 |
| 英文通用 | 0.20 |
| 代码 | 0.15 |
| 数学 | 0.10 |
| 论文 | 0.00 |
| 百科 | 0.05 |

这套配比相对偏向中文，同时保留英文、代码、数学和百科能力。由于当前试训练中发现中文生成存在重复和网页污染问题，后续需要提高中文高质量数据比例，特别是引入更干净的中文教育类网页、百科和 Wiki 数据。

## 4. Tokenizer 训练与验证

开题报告中计划从清洗后的多源数据中采样约 200GB 文本，训练 150K 规模的 SentencePiece BPE 词表。在实际实现中，早期尝试使用 200GB 采样语料训练 tokenizer，但训练过程中内存压力过大，无法继续训练，因此改为 50GB 采样规模；同时为了获得更好的训练速度、进度可观测性和工程可控性，最终采用 HuggingFace Byte-level BPE 训练框架。根据后续 inspection 结果，50GB 语料已经能覆盖当前多领域训练需求。

当前 tokenizer 配置位于 `configs/tokenizer/hf_byte_bpe_150k.yaml`，主要参数如下：

| 项目 | 当前设置 |
| --- | --- |
| 算法 | HuggingFace Byte-level BPE |
| 词表大小 | 150000 |
| 训练线程 | 64 |
| 输出路径 | `runs/stage0_data_tokenizer_hf/tokenizer/llmtrain_hf_byte_bpe_150k.json` |
| 特殊 token | `<unk>`、`<s>`、`</s>`、`<pad>`、`<|system|>`、`<|user|>`、`<|assistant|>`、`<|tool|>`、`<|endoftext|>` |

Tokenizer inspection 结果位于：

```text
runs/stage0_data_tokenizer_hf/tokenizer_inspection.json
```

检查时按领域抽样，每个领域使用 1000 条样本，共 5000 条。核心结果如下：

| 领域 | 样本数 | 字符数 | Token 数 | chars/token | byte fallback token |
| --- | ---: | ---: | ---: | ---: | ---: |
| 中文 | 1000 | 964779 | 512927 | 1.88 | 0 |
| 英文 | 1000 | 2643571 | 580043 | 4.56 | 0 |
| 数学 | 1000 | 53894065 | 16189667 | 3.33 | 0 |
| 百科 | 1000 | 2746127 | 755244 | 3.64 | 0 |
| 代码 | 1000 | 9831011 | 3226561 | 3.05 | 0 |

从结果看，当前 tokenizer 在中文、英文、数学、百科和代码域均未出现 byte fallback 异常，压缩率也符合预期。中文约 1.88 chars/token，说明中文场景下词表对常见片段已有较好覆盖；英文、代码和数学文本的压缩率也处于可接受范围。

## 5. 训练框架构建进展

当前训练框架已经从脚本式实验推进到可配置、可恢复、可测评的工程结构。主要进展包括：

1. 配置系统已经成型。训练配置通过 YAML 组合数据、tokenizer、模型和 trainer 配置，700M 训练入口为 `configs/train/stage1_general_700m.yaml`。
2. 模型结构已支持 Qwen-like Transformer。700M 配置为 24 层、hidden size 1536、16 个 attention heads、8 个 KV heads、上下文长度 4096、词表大小 150K。
3. 数据加载已经支持流式 manifest 读取、领域混合采样、packing 和异步 tokenization。
4. 训练入口 `run.py` 已支持 train、infer、eval 子命令，并封装多卡启动参数。
5. 多卡训练已接入 FSDP，checkpoint 已切换到 DCP 自动模式，支持保存模型权重和优化器状态。
6. 推理入口支持 checkpoint 加载、流式输出、KV cache 和 DCP checkpoint 兼容。
7. 测评入口已经接入 lm-evaluation-harness，支持多卡测评、离线数据集、结果和样本分文件保存。
8. 观测能力已经包括训练 metrics、heartbeat、data metrics、进度条和训练数据消费速度统计。

这些实现与开题报告中“基于 PyTorch FSDP 实现多卡分布式训练”“构建流式数据加载、checkpoint 保存、验证集评估与训练日志记录机制”的工程目标直接对应。目前已经完成的是预训练框架和评测框架主体；SFT、reasoning cold-start 和 GRPO 的训练逻辑属于下一阶段继续推进的内容。

700M 当前训练配置要点如下：

这些模块的完成意味着后续 1.7B 训练不需要从零搭建训练系统，而是可以在当前训练配置和数据质量基础上继续扩展。

## 6. 700M 模型试训练与测评结果

### 6.1 试训练过程

当前已完成 700M 规模模型的 v2 试训练。第一次训练在约 1.2B tokens 左右发现生成结果存在明显重复，随后对训练超参数进行了调整：放慢学习率衰减节奏，减小 global batch size，使模型更新更频繁，并重新进行 v2 训练。

v2 训练已经产生从 0.1B 到 10B tokens 的多个 milestone checkpoint，checkpoint 目录包括：

```text
runs/stage1_general_700m_v2/checkpoints/
```

这些 checkpoint 已用于测评曲线绘制和不同训练阶段能力对比。

### 6.2 测评任务选择

由于当前模型只做预训练，没有进行指令微调或 RLHF，因此测评任务优先选择与预训练目标更接近的续写 / 完形填空任务：

- Chinese WPLC：中文完形填空类任务，用于观察中文语言建模能力；
- LAMBADA：英文长距离上下文预测任务，用于观察英文续写与上下文理解能力。

同时，我们发现现有中文Benchmark大多面向instruction/chat模型、考试能力或下游任务，但缺少能在**预训练早期阶段**稳定追踪大模型**基础语言能力**增长的评测集。因此，我们很难在小算力规模与时间成本的情况下，验证模型的收敛是否正确，以及数据配比和质量是否可靠。这类Benchmark的构建也将是我们未来的研究方向。

测评配置位于 `configs/eval/stage1_general_700m.yaml`，结果目录为：

```text

```

### 6.3 阶段性结果

| 训练量 | Chinese WPLC acc | Chinese WPLC ppl | LAMBADA acc | LAMBADA ppl |
| ---: | ---: | ---: | ---: | ---: |
| 1B tokens | 3.05% | 21343.94 | 2.52% | 10110.23 |
| 5B tokens | 4.60% | 2234.11 | 19.56% | 220.82 |
| 10B tokens | 5.10% | 1509.70 | 25.40% | 103.82 |

从曲线看，英文 LAMBADA 随训练量增加提升较明显，从 1B tokens 的 2.52% 提升到 5B tokens 的 19.56%，并在 10B tokens 达到 25.40%。中文 WPLC 也有提升，但整体仍明显偏低，从 1B tokens 的 3.05% 提升到 10B tokens 的 5.10%，最好结果约为 5.26%，与人类准确率 57.3% 仍有较大差距。

对比参考结果，GPT-2 762M 在 LAMBADA 上可达到约 60.1%。当前 700M 模型尚未达到同规模成熟模型水平，但考虑到本项目当前仍处于从零训练的试验阶段，并且训练量只有 10B tokens，该结果已经验证了训练框架、数据流、checkpoint、推理和测评链路的有效性。

## 7. 当前问题与风险分析

### 7.1 中文数据质量不足

从一些推理样例看，当前中文生成存在明显的网页模板、广告文本和重复污染。例如围绕“北京小吃网”和“火锅行业”的生成会反复出现站点介绍、投资创业等低质量片段。这说明当前中文通用语料中仍存在较多低质量网页内容，模型在较小训练量下容易学习到重复模式。

prompt为“火锅”时的生成结果：
> 行业:火锅行业受资本青睐随着火锅行业的快速发展,火锅行业也迎来了发展的黄金时期,很多火锅行业创业者都纷纷开始创业。火锅行业作为火锅行业的细分行业,其行业发展前景也是非常广阔的。那么,火锅行业前景如何呢?投资火锅行业有哪些好的项目?1、投资火锅行业的好项目,是投资火锅行业的绝佳项目。投资火锅行业,投资创业,投资创业,投资创业,投资创业,投资创业,投资创业,投资创业......

prompt为“北京小吃”的生成结果：
> 网 北京小吃网 是为京城内餐馆提供美食信息的网站.提供北京小吃信息.北京小吃网 为京城内餐馆提供美食信息的网站.北京小吃网 ,北京小吃网 是一家全国性的餐饮信息门户网站,是北京市政府重点扶持的餐饮企业.网站由北京小吃网 提供,北京小吃网 网站信息免费提供给用户,免费提供北京小吃信息,提供北京小吃信息.网站简介 : 北京小吃网 是以介绍、介绍北京小吃为主,以北京小吃信息为主,提供北京小吃信息,提供北京小吃信息,为京城内餐馆提供美食信息的网站..

后续需要从两方面改进：

- 增加高质量中文数据，例如 chinese-fine-web-edu-v2.1、百科、Wiki、教材或高质量问答文本；
- 加强预处理阶段对模板化网页、SEO 内容、重复段落和广告文本的过滤。

### 7.2 中文测评提升有限

Chinese WPLC 从 1B 到 10B tokens 有提升，但提升幅度不如 LAMBADA 明显。可能原因包括：

- 中文数据质量不稳定；
- 该测评集的数据全部取自中文网络小说，其语言分布可能与训练数据集的网页语料存在较大不同。
- 当前数据配比中百科和高质量中文知识文本比例偏低；
- 700M 模型和 10B tokens 训练量对中文常识和完形填空任务仍不足；
- 当前模型未经过任何指令或任务格式适配。

因此后续不能仅依赖增加训练 token 数，还需要同时提升中文数据质量和领域配比。

### 7.3 论文域尚未进入训练

开题规划中论文数据是重要组成部分，但当前训练混合中 paper 权重为 0。这样可以降低早期试训练的不确定性，但也意味着模型目前尚未验证论文解析数据对训练的影响。后续需要在 MinerU 论文解析数据质量稳定后，将 paper 域逐步加入训练，并观察对长文本、科技文本和推理能力的影响。

### 7.4 测评覆盖仍然有限

当前测评只覆盖 Chinese WPLC 和 LAMBADA，适合预训练模型，但不能完整评价模型能力。后续至少需要补充：

- 中文语言建模和常识类测评；
- 数学和代码补全测评；
- 更细粒度的 perplexity 分域评估；
- 后训练完成后的指令跟随和对话能力测评。

## 8. 后续工作计划

下一阶段的重点是从“完成试训练闭环”转向“提升数据质量、启动更大模型训练，并衔接开题报告中的后训练目标”。计划如下：

1. 数据质量改进：优先处理中文污染问题，提高中文高质量数据和百科数据比例，减少 SEO、广告和模板重复文本。
2. 数据配比迭代：在当前 zh/en/code/math/wiki 基础上，逐步引入 paper 域，并观察对训练稳定性和评测结果的影响。
3. 启动 1.7B 通用预训练：复用当前 FSDP、DCP、异步 tokenization 和 eval pipeline，目标训练量 20B-50B tokens。
4. 扩展评测体系：在保留 Chinese WPLC 和 LAMBADA 的基础上，增加中文、代码、数学和分域 perplexity 评测。
5. SFT 与推理冷启动准备：按照开题报告规划，后续使用中英双语指令数据进行 SFT，并使用推理链数据进行 reasoning cold-start。
6. GRPO 后训练闭环：在基础模型和冷启动模型稳定后，基于可验证数学任务实现 rollout、reward、train worker 的串行 GRPO 流程。
7. 推理方向继续预训练：在 1.7B 通用预训练稳定后，提高数学、代码、STEM 和推理数据比例，进行 2B-10B tokens 的 reasoning continual pretraining。
8. 长上下文继续预训练：资源允许时，将上下文长度从 4096 扩展到 8192、16384，最终尝试 32768。

## 9. 阶段完成度评估

综合当前进展，项目已经完成从数据到模型的核心工程闭环：

- 数据集下载和预处理流程已经完成主要实现；
- tokenizer 已完成训练和多领域验证；
- 训练框架已经支持配置化、多卡 FSDP、DCP checkpoint、异步 tokenization 和观测指标；
- 700M 模型已经完成 10B tokens 试训练；
- 推理和测评入口已经可用；
- 已经形成 Chinese WPLC 与 LAMBADA 的多 checkpoint 评测曲线。

按照开题规划，当前已经完成阶段 0A、0B 和 0C 的主体工作，并为阶段 1 的 1.7B 通用预训练完成了工程准备；同时推理入口、测评入口和 checkpoint 机制也为后续 SFT、reasoning cold-start 和 GRPO 提供了可复用基础。因此当前整体完成度评估为 **35%-40%**。后续主要工作不再是搭建预训练基础框架，而是围绕数据质量、训练规模、测评体系、1.7B 正式训练和后训练闭环继续推进。
