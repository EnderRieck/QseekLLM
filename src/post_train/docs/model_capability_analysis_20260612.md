# 模型能力分析报告:F2/S3-R1 vs Qwen3-1.7B · 2026-06-12

> 通过抽样对比作答,定位当前模型(1.6B)的真实能力边界与缺陷性质,
> 校准后续 SFT/RL 路线。**核心结论在 §6:当前"堆难题"路线可能跑偏,
> 模型缺的是 L1-L3 基本盘,不是难度。**

---

## 1. 背景与对象

**我们的模型谱系(单链,每段从上段终档热启)**:
```
qseek_digitsplit_base(1.6B,数字切分 tokenizer,他人预训练)
  → F2  = sft_foundation_v2 / step 9858  (阶段1-2:广度打底+算术执行+格式对齐)
  → S3-R1 = sft_s3r1 / step 3874         (阶段3:难度课程,引入 R1 长链,ctx 16k)
  → S4  = sft_s4_anneal / step 1140      (阶段4-SFT:难题退火,hard 38%,lr→2e-7)
  → (GRPO RL,未开始)
```

**对比基线**:
- `Qwen3-1.7B-Instruct`:成熟 instruct 模型,按 boxed 格式作答,判分口径与我们一致 → **最公平的对照**。
- `Qwen3-1.7B-Base`:能力强但**不输出 `\boxed`**,答案写在散文里 → 判分器系统性低估(format=0%,且多次出现"算对被判错"),其数字**仅供参考,看 Instruct 列**。

**判分口径**:本报告所有 pass@1/pass@8 均用**修复后的判分器**(`data_pipeline.reward`,
2026-06-12 修了 math_verify 裸串 bug + mcq 裸字母假阳)对存档 generations 离线重判,三模型同口径。

**为什么做这个分析**:S4 训完后,过程评测 acc 横盘在 38%。想搞清楚"模型到底训成什么样",
于是抽样读实际作答(而非只看数值),并补跑 S3-R1/S4 终评(此前缺失)。

**权重相对 S3-R1 max|Δ|≈0.001(几乎没动)**,所以性能也几乎没变。
**结论:难题退火这一步对当前模型既没用也没害,是一步白训。** RL 起点仍取 S3-R1
(pass@8 最高、收割带最宽,且不比 S4 差)。

## 3. 与 Qwen 的差距:难度切片

**math500 by level(pass@1)**:F2 在 Level 1 就只有 11.6%(Qwen-Inst 69.8%),
即**竞赛数学的最低档对 F2 都近乎不可解**。

**cmath by grade(pass@1)**:F2 一年级 65.9%(反超 Qwen-Inst 64.6%),但逐年级断崖——
六年级仅 21.7%(Qwen 55%)。**F2 能力边界 ≈ 小学低年级单步题,过线即崩。**
Qwen 曲线平缓(全程会做,难题正确率低),F2 是"难一点就不会"。

**错因分解**:F2 答错的题里,**格式规范却算错占 97-100%**(gsm8k 97%/cmath 98%/svamp 100%)。
即 F2 几乎从不"格式崩",全是**排版工整地算错**。**瓶颈 100% 在推理内核,不在格式。**

## 4. 抽样 case:F2 缺陷的五层病理

抽样 ~14 道(F2 错 / Qwen 对),缺陷按层次归类。每类附一个代表样本(完整原文见各 final_eval/<bench>.jsonl)。

### 4.1 解析层 —— 读不准数学表达式
**math500 idx20**:`Evaluate (1+2i)6-3i`(应 =6+9i)。F2 把 `(1+2i)6-3i` 读成
`(1+2i)(6-3i)` 两复数相乘 → 全错。**把"6−3i"脑补成括号整体。**

### 4.2 概念层 —— 量纲/变量常数/等式守恒,统统缺失
- **量纲不分(影响最广)** gsm8k idx9:Eliza 分段时薪题,F2 把"周薪$400"当 rate 再×1.2、
  再×45h,$10→$400→$480→$2520,**分不清 $/hour 与 $**,结果大5倍无察觉。
- **变量当常数** math500 idx98:`(-k+4)+(-2+3k)`,F2 把 `-k` 写成 `-2`,k 项凭空消失。
- **无等式守恒** math500 idx79:`2³·3ˣ=72`,F2 推出 `32=72` 照样往下走,给 x=1。

### 4.3 建模层 —— 只会线性硬怼,不会分段/逆推/换算
- cmath idx656:林场面积→公顷→棵数,F2 用 `/100`(误以为 1公顷=100㎡)、且无"面积"中间量。
- cmath idx661:平均数改动逆推,F2 列式方向反(改后均值变大却算出原数更大)。

### 4.4 程序层 —— 解题套路只有外壳,无实际操作
- math500 idx312:`1/(x-5)>0`,F2 摆出 Case1/Case2 架势,但**不判断每类下分式是否真>0**,
  两类全收进答案 → `(-∞,5)∪(5,∞)`(应 `(5,∞)`)。
- math500 idx102:分组分解 `ab+5b+2a+10`,F2 说"factor out / group"但操作全乱,
  写出 `b+5(a+1)=b+5(a+1)` 废话,给半成品。
**它学会了术语和步骤框架,没学会框架背后的代数/逻辑判断——形似神不似。**

### 4.5 执行层 —— 漏步 / 多余动作(RL 可修)
- gsm8k idx6:羊群三地求和,F2 每步算对,**只漏最后 160+80+20**,拿分量交卷。
- gsm8k idx11(甜甜圈,8采样命中3):贪心多此一举把"打"换成"个"再×每打价(量纲错);
  **采样中3条直接"打数×每打价"走对**。← RL 收割带的活样本。

### 病理总览
| 层 | 病症 | 性质 |
|---|---|---|
| 解析 | 读不准数学符号 | 基础 |
| 概念 | 量纲/变量常数/等式守恒缺失 | **最本质,影响全题型** |
| 建模 | 线性硬怼,无结构化 | |
| 程序 | 套路空壳,无实质操作 | |
| 执行 | 漏步/冗余 | RL 可修 |

**一句话画像:F2 被 SFT(尤其 compute_cot 的"列式:→逐步求值"模板)训出了
"解题的样子"——格式、术语、步骤框架都像,但支撑形式的实质能力(可靠符号操作、
概念锚点、逻辑判断)几乎是空的。它在表演解题,不是在解题。**
注:纯数学题崩塌**不能赖"工作记忆小"**——`(-k+4)+(-2+3k)` 信息量极小也照崩,
说明是符号操作精度与概念扎实度的根本不足。

## 5. RL 可收割带(pass@8 重判,F2)

"部分命中带(8采样对1-7次)"= GRPO 唯一有梯度的区域(全错/全对均零梯度)。

| bench | pass@8 | 收割带 | 全错(0/8) | 全对(8/8) |
|---|---|---|---|---|
| svamp | 69.7% | **65%** | 30% | 4% |
| cmath | 60.8% | **45%** | 39% | 16% |
| gsm8k | 40.9% | **40%** | 59% | 0% |
| math500 | 18.4% | 18% | **82%** | 0% |

- **F2 全对组≈0、收割带宽**(高熵噪声型),正是 RL 最易固化的形态。
- **svamp/cmath/gsm8k 有 40-65% 收割带 → RL 可直接发力**(回答了"高熵能否自然学会":这几档**能**)。
- **math500 82% 全错 → RL 零梯度,无效**(那道 f(x) 即此类);得靠 SFT 先把它顶进收割带。
- RL 近期天花板 ≈ pass@8:gsm8k~41%、cmath~61%、svamp~70%、math500~18%。

## 6. 核心结论:加难度这条路收益递减(但 S4 没崩,是误判)

**证据链**:① S3-R1 难度课程在 pass@1 上 ≈ F2(贪心无提升),仅 pass@8 略抬;
② case 显示 F2 病根在 L1-L3 基本盘(量纲/符号/程序空壳),非难度;③ 竞赛档 82% 全错组,
难题数据对当前模型大多是无梯度噪声;④ **S4 退火健康但零收益**——四档 ≈ S3-R1、略降一线
(权重相对 S3-R1 几乎没动,见 §2 发现②)。

**判断**:**"堆难题 + R1 长链 + 退火"这条 SFT 加码路线,对基本盘不牢的模型收益递减到零。**
F2→S3-R1→S4 三段,benchmark 上基本横盘:难题学不动(全错组无梯度),退火又几乎不动权重。
F2 真正缺的是**规范的基础数学演算能力**(正确的符号代入、量纲守恒、等式操作、套路的实质执行),
而我们一直在加难度——**方向使错了力**(不是"练崩",是"白练")。

**一个被 pass@1 掩盖的正面信号**:S3-R1 虽贪心不动,但 **pass@8 在 gsm8k 抬升**
(§2 发现①),说明难度课程**略微扩宽了 RL 收割带**。所以 S3-R1 是比 F2 略好的 **RL 起点**。

**行动结论**:① **RL 起点取 S3-R1**(pass@8 最高、收割带最宽,S4 不优于它且白训一轮);
② 后续 SFT 改向"补基本盘"而非"加难度"(§7);③ RL 重仓收割带中低档,竞赛档暂不进(§5/§7)。

> **纠错记录**:本节初版曾据"S4 svamp 1.7 崩塌"判 S4 失败、称退火"把苗拔死"。
> 该数据系评测 bug(裸底座,§9),已作废。重评后 S4 健康、≈S3-R1。结论由
> "S4 练崩、路线有害"修正为"S4 白训、路线收益递减"——**对 RL 起点取 S3-R1 的决策无影响**。

## 7. 建议

1. **先补基本盘,而非难度**:数据侧加大"规范基础演算"示范(numina/openr1 里每步合法、
   守恒的 L1-L3 代数/算术演算),而非竞赛难题。重新审视 compute_cot 占比——其"列式:"
   模板疑似强化了"不理解先硬算"的坏习惯(见 §4 中文题)。
2. **RL 用于收割带,不用于难档**:RL 课程重仓 svamp/gsm8k/cmath 中低档(收割带 40-65%),
   竞赛档先不进 RL。RL 的价值在"形神兼备的轨迹已存在时放大它"(§4.5 甜甜圈)。
3. **退火配方重审**:S4 这轮 lr 2e-6→2e-7、1140 步,权重几乎没动→零收益。若仍要退火,
   要么提高有效学习量(lr/步数),要么干脆跳过这步、把算力投到"补基本盘"数据上。
4. **判分器**:Qwen-Base 类无 boxed 输出被系统性低估,跨模型对比须用同格式模型(Inst)。
5. **修评测管线静默失败**(§9):`convert_to_hf` 找不到 `.pt` 应直接 raise,不许 fallback 到 base。

## 9. 评测管线 bug 复盘:S4"假崩塌"事故

**现象**:S4 终评 svamp pass@1=1.7、fmt 8.7%,输出退化成复读"...0001...wordr wordr",
一度判定"退火练崩"。

**根因(两个缺陷叠加)**:
1. `eval/final_eval.py:249` 用"`ckpt/config.json` 是否存在"判断要不要转换。S4 终评误传
   `--ckpt …/global_step_1140_hf`——该目录只有 `final_eval/` 子目录、无 config.json/无 `.pt`
   (真权重在 `…/global_step_1140/` 的 `model_world_size_1_rank_0.pt`)。
2. `eval/async_eval.py:70` `convert_to_hf` 里 `if ckpt_pt:`——`find_ckpt_pt` 找不到 `.pt`
   时**不报错**,直接 `model.save_pretrained` 把 `args.base`(裸预训练底座
   `qseek_digitsplit_base`)原样存成 `…_hf_hf`。
   → 评的是**零 SFT 的底座**,与 S4 无关。

**确认**:`…_hf_hf/model.safetensors` 的 `embed_tokens` 与 `qseek_digitsplit_base`
**逐字节相同(max|Δ|=0)**;用 FSDP `.pt` 正确转换得到 `…_HFFIX` 后 vs base max|Δ|=0.036、
vs S3-R1 max|Δ|=0.001,重评 svamp 42.0/72.3——健康。

**修复建议**:① `convert_to_hf`:`ckpt_pt is None` 时 `raise`,禁止静默 fallback 到 base;
② `final_eval.py`:判定"已是 HF 目录"应同时检查 `*.safetensors` 存在,而非仅 config.json;
③ 命名规范:别把 `_hf` 追加到本就含 `_hf` 的路径上(`_hf_hf` 这种双后缀即危险信号)。

> **状态(2026-06-12 夜·定稿)**:F2/S3-R1/S4 三模型 4-6 bench 终评齐(同口径)。
> §2 表格为最终值。**核心订正:S4 非崩塌,系评测 bug;实测 S4≈S3-R1、退火零收益。**
> RL 起点取 S3-R1。bug 待按 §9 修复。
